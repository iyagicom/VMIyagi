# VMIyagi

이야기 시리즈 deb를 **깨끗한 우분투에서** 검증하기 위한 개발용 VM 관리 도구.

"내 PC에서는 되는데"를 없애는 것이 목적입니다. 아무것도 깔려 있지 않은 우분투에
deb를 설치하고, 실행되는지 보고, 다시 깨끗한 상태로 되돌리는 과정을 반복합니다.

VirtualBox나 GNOME Boxes를 대체하려는 물건이 아닙니다. QEMU/KVM 위에 얹은 얇은
프런트엔드이고, 이 반복 작업에 필요한 것만 있습니다. 화면은 한국어와 영어를 지원합니다(시스템 언어가 한국어면 한국어, 그 밖은 영어).

---

## 필요한 것

- QEMU/KVM (`qemu-system-x86_64`, `qemu-img`) — KVM 사용 가능한 CPU
- Qt 6.11 이상 (다른 이야기 시리즈와 동일하게 `~/Qt/6.11.1/gcc_64`)
- 우분투 설치 ISO (VM별로 최초 1회)

```bash
QT_PREFIX=$(ls -d "$HOME/Qt"/*/gcc_64 | sort -V | tail -1)
cmake -S . -B build/linux-release -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$QT_PREFIX"
cmake --build build/linux-release -j$(nproc)
./build/linux-release/VMIyagi
```

## 처음 한 번: VM 만들기

1. **실행** — 베이스 디스크가 없으면 설치용 ISO를 고르라고 합니다. 40GB 디스크가
   만들어지고 ISO로 부팅합니다
2. 평소처럼 우분투를 설치합니다. **계정 이름은 `iyagi`로** (자동화가 이 계정으로 접속합니다)
3. 설치 후 게스트에서 `apt update && apt full-upgrade` 까지 끝냅니다
4. **게스트 준비** — 아래 참조
5. 게스트를 종료하고 **스냅샷 저장** (이름 `Clean`)

이제 **초기화**를 누르면 언제든 5번 시점으로 돌아갑니다.

## 게스트 준비 (VM당 1회)

우분투 **데스크톱** ISO에는 SSH 서버도, 클립보드 공유 도구도 들어있지 않습니다.
자동화가 게스트 안으로 들어갈 방법 자체가 없기 때문에 한 번은 사람이 열어줘야 합니다.

**게스트 준비** 버튼을 누르면 공유폴더에 준비 스크립트가 생깁니다. 게스트 터미널에
표시된 한 줄을 붙여넣어 실행하면 됩니다:

- openssh-server, spice-vdagent, xclip, wl-clipboard 설치
- VMIyagi 공개키 등록 (`~/.ssh/vmiyagi_ed25519`, 없으면 자동 생성)
- 공유폴더 `/mnt/build` 자동 마운트 등록
- 패키지 명령(apt/dpkg/systemctl)에 한해 비밀번호 없는 sudo 등록

클립보드가 아직 안 되는 상태라 붙여넣기가 안 되면 **게스트에 명령 입력**을 쓰세요.
QEMU 모니터로 키를 직접 쳐 넣기 때문에 클립보드가 필요 없습니다.

준비가 끝나면 **연결 테스트**로 확인하고, 종료 후 **스냅샷 저장**으로 Clean에 반영하세요.
반영하지 않으면 초기화할 때 준비 상태가 같이 날아갑니다.

## 평소 사용

| 버튼 | 하는 일 |
|------|---------|
| 실행 / 종료 | VM 켜고 끄기 (종료는 ACPI 요청) |
| 초기화 | Clean 스냅샷 상태로 되돌리기 |
| 스냅샷 저장 | 현재 상태를 스냅샷으로. 같은 이름이면 **합쳐서 갱신**합니다 |
| 복제 | 원본과 파일을 전혀 공유하지 않는 독립 VM 만들기 |
| 스냅샷 관리 | 스냅샷 목록/삭제 (다른 스냅샷이 쓰고 있으면 삭제를 막습니다) |
| 게스트 준비 | 위 참조 + 연결 테스트 / 클립보드 진단 |
| 게스트에 명령 입력 | 클립보드 없이 게스트에 명령을 타이핑 |
| **Run Test** | 이야기 시리즈 최신 deb를 골라 설치·실행하고 로그 저장 |

### Run Test

`<프로젝트>/build/**.deb` 를 훑어 **프로젝트별 최신 deb 하나씩** 보여줍니다. 고르면:

1. 빌드 폴더로 복사 (= 게스트의 `/mnt/build` 에 바로 보입니다)
2. `apt-get install` 로 설치 — 의존성까지 실제로 끌어오는지 봅니다
3. 패키지가 설치한 실행 파일을 찾아 게스트 데스크톱에서 실행
4. 8초 뒤에도 살아있는지 확인
5. `logs/<vm>_<앱>_<시각>.log` 에 전체 기록

**깨끗한 상태에서 보려면 먼저 초기화한 뒤 실행하세요.** 그래야 "새 PC에서 되는가"를
보는 것이지, 이미 의존성이 깔린 VM에서 되는 걸 보는 게 아닙니다.

### 클립보드 / 화면

- 호스트와 게스트 사이 복사·붙여넣기는 VM을 **실행할 때** 자동으로 연결됩니다.
  로그에 `클립보드 연결됨`이 뜨면 준비된 것입니다
- 목록에 **"Running (앱 밖에서 실행 중)"** 으로 보이는 VM은 이전 앱 인스턴스가 띄운
  것입니다. 클립보드와 로그가 끊겨 있으니 껐다 켜세요
- 게스트가 떨리거나 화면이 이상하면 **화면 방식**을 `virtio (GL 끔)` → `안전` 순으로
  바꿔 보세요. 다음 실행부터 적용됩니다

## 주의

- **VM 디스크는 백업되지 않습니다.** 스냅샷은 서로 차이(diff)로 연결돼 있어서,
  파일 탐색기에서 `vms/` 안을 직접 지우면 다른 스냅샷까지 깨집니다. 삭제는 반드시
  **스냅샷 관리**를 통해서 하세요
- 게스트 계정 이름이 `iyagi`가 아니면 SSH 키 인증이 거부됩니다
- 네트워크는 QEMU user 모드(NAT) 고정입니다. 브리지/포트포워딩 설정은 의도적으로
  노출하지 않습니다 — 이 도구가 풀려는 문제가 아닙니다

구현 배경과 함정은 [DEVNOTES.md](DEVNOTES.md)에 정리돼 있습니다.
